# Лабораторная работа №4: доп²

**Задание:** Необходимо развернуть UDDI на Helios так, чтобы к нему был доступ из внешнего мира (то есть по [se.ifmo.ru/~s367081/...](https://se.ifmo.ru/~s367081/soa/lab4/)).

## Как запустить?

Сначала в [application.yml](../src/main/resources/application.yml) укажем порт, на котором будет работать сервис (здесь используется `15613`).

Локально собираем `.jar`:

```bash
cp .env.example .env
nano .env # меняем значения в .env на свои для вашей БД на Helios
export $(cat .env | xargs)
./gradlew bootJar
```

В `./build/libs/uddi.jar` получаем итоговый файл `uddi.jar` со всеми зависимостями. Переносим его на Helios:

```bash
scp -P 2222 ./build/libs/uddi.jar sXXXXXX@se.ifmo.ru:~/
```

Далее переносим `.env`, либо создаем его уже на Helios.

Запуск:

```bash
export $(cat .env | xargs) # устанавливаем переменные окружения
java -jar uddi.jar
```

После этого на порту `15613` (или том, который вы указывали) запустится Spring Boot приложение UDDI.

## Как проксировать запросы на Helios?

Чтобы перенаправлять запросы, которые приходят из внешней сети на приложение, работающее на каком-то порту внутри, нам придется написать свой proxy на PHP (ибо как-то по-другому это сделать на Helios у нас не хватит прав).

Перейдем в директорию `public_html`:

```bash
cd ~/public_html
```

Далее можете использовать любой путь, какой будет угодно (например, файлы, которые вы положите по пути `/home/studs/s367081/public_html/soa/lab4/additional-task`, будут доступны на [se.ifmo.ru/~s367081/soa/lab4/additional-task/](https://se.ifmo.ru/~s367081/soa/lab4/additional-task/)).

По вашему расположению вставьте эти файлы (в коде измените порт с `15613` на ваш):

- [`proxy.php`](./proxy.php) — главный файл прокси, который принимает SOAP запросы и перенаправляет их на Java UDDI сервис. Использует `file_get_contents()` вместо `cURL` (так как `cURL` недоступен на сервере).
- [`ui.php`](./ui.php) (_опционально_) — пользовательский интерфейс для ручного тестирования SOAP запросов через браузер.
- [`test-direct.php`](./test-direct.php) (_опционально_) — скрипт для проверки возможности прямого подключения к Java UDDI сервису из PHP.
- [`test-php.php`](./test-php.php) (_опционально_) — минимальный скрипт для проверки конфигурации PHP сервера.

## Как это работает?

1. Клиент отправляет SOAP запрос на `proxy.php`;
2. Прокси принимает запрос, логирует его;
3. Прокси перенаправляет запрос на Java сервис;
4. Java сервис обрабатывает запрос и возвращает ответ;
5. Прокси возвращает ответ клиенту.
